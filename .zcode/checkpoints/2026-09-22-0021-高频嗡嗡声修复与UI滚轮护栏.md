## 3. 高频嗡嗡声：诊断与修复（本节是本轮重点）

**根因**：`core/bwe.py` 的频段平衡规则是"把生成频段压到通带之下 12 dB"——这是一个**绝对电平目标，本身不带方向性**。当模型原始高频本来就安静时，它反过来变成巨额放大。实测（真实素材经 deepfilternet3 降噪后的 30 s 片段）：

- NovaSR 的**原始**输出在 9–16 kHz 比通带低约 **42–55 dB**（它确实几乎没补什么）；
- 平衡据此算出 **g_hf = +31.56 dB**，把模型的宽带本底整体抬高；
- 抬高后 1 kHz 细带在 **13–14 kHz 达到峰值（只比通带低 16.5 dB）**、形状随频率**上升**，而源素材在 9 kHz 以上是 −85 dB 的硬悬崖。这就是听到的那层嗡嗡声。

**排除掉的三个嫌疑**（都留了数字）：

| 嫌疑 | 实测结论 |
|---|---|
| 离散啸叫 | 确有一条 16002 Hz 线，但只有 **−83.6 dBFS**（相对通带 −50 dB），且停顿段近乎数字静音 ⇒ 按绝对电平听不见 |
| 上采样成像（通带的镜像副本） | 用**平坦度**判据否证：镜像副本应只差一个常数增益，而实测离散度 **12.2 dB**（通带自身对照仅 0.35 dB）。先前看到的 r=0.87 只是两条谱整体倾斜相似 |
| GPU / TF32 / 喂错采样率 | CPU 与 CUDA 的高频电平差 0.2 dB、差信号 −60 dBFS 且无线条；给模型喂 48 kHz 与 16 kHz 的原始输出**逐带一致**（audiosronnx 自己会重采样到 16 kHz） |

**修复**：`balance_gains` 加放大上限（`MAX_HF_BOOST_DB = 0.0`，只压不抬）。

**修复后实测**（同链 `deepfilternet3 + NovaSR`，相对通带）：13–14 kHz **−16.5 → −48.8 dB**；8–9 kHz −31.2 → −61.5 dB；8 kHz 交叉点台阶 **+8.1 → −3.0 dB**。**原缺陷④的修复未被破坏**：lavasr 那类"高频过强"的输出仍被从 +16.2 dB 压到 −10.8 dB（g_hf = −33.1 dB）。

**给用户的可试听对照**（写在项目 `out/`，同一素材同一条链，只差这条护栏）：
`_对比_源片段.wav`、`_对比_高频嗡嗡声_修复前.wav`、`_对比_高频嗡嗡声_修复后.wav`
