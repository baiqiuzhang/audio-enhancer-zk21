## 4. 测试及结果

**15 / 15 套件 EXIT=0**（最终版本；`check_gpu` 为新增第 15 个）

**关键实测结论（三条与计划相反）**

1. **线程数「2→4」被否证。** 三个模型（DPDFNet2 / GTCRN / DPDFNet8）一致：1 与 2 线程等价，**4 线程起慢 11–25%**，8 线程更慢。首尾各跑一次相同配置验证漂移仅 1.8%，所以不是发热/顺序。→ **默认保持 2，不要往上调**（README 与界面原写的"收益在 2–4 见顶"是未实测的错误陈述，已更正）。
2. **sherpa 上 CUDA 反而慢 6.3–6.6 倍。** CPU RTF 0.126 / CUDA RTF 0.842（30 s 与 60 s 两段、重复 2–3 次，方差 ±0.5%，比值与长度无关）。→ `sherpa_provider="auto"` **明确选 CPU**，要 GPU 必须显式指定。
3. **`attenuation_limit_db = 0` 是「不设上限」，不是「不降噪」。** 白噪声实测：0 → 衰减 69.3 dB，而 3/6/12/18/30 → 3/6/12/18/30 dB。真实素材上 `0` 把最安静帧压到 −107.8 dBFS。而 **6/12/18 之间几乎测不出差别**（底噪降幅都是 21.1 dB、RMS 差 <0.3 dB）→ 预设都不动它是实测支持的。

**顺带更正的三处错误陈述**（都属"未验证的推断被当成事实"）：

- README 的降噪强度行原写「0 dB ≈ 不降噪」→ **反了**。
- README 的 LavaSR RTF 1.94「比实时还慢」→ **未复现**（实测 0.129，与 NovaSR 0.124 几乎一样快；用户自己 21:04 的日志也反证）。
- 本项目早先版本（及上一份检查点）称 README 里写着「输出率 = 模型原生率」→ **README 从未写过**（`原生率` 命中数为 0，仅我本轮新增的两处提到它）。错的是那次推断本身，不是文档。已在 README 与 `core/pipeline.py` 注释里改正措辞。

**GPU 实测数字**

| 环节 | CPU | CUDA | 结论 |
|---|---|---|---|
| 带宽扩展 NovaSR（20–28.8 s） | RTF 0.066–0.083 | RTF 0.041–0.053 | **快 1.48–1.65×** → auto 选 CUDA |
| sherpa 降噪 DPDFNet2（30 s） | 3.79 / 3.90 s | 25.18 / 25.26 / 25.41 s | **慢 6.6×** → auto 选 CPU |

CPU/GPU 数值等价性（设备不进指纹的前提）：BWE 最大逐样本差 1.06e-03 / 相对 RMS 0.54%；降噪 2.18e-05 / 0.010%。**不是逐位相同**。

**分阶段耗时（18 分钟立体声整段，listen 预设，420.0 s）**：降噪推理 261.9 s（62.4%）、带宽扩展 123.3 s（29.4%）→ **推理占 91.8%**；解码 1.8 s、**重采样 0.00 s**、写出 0.67 s（310 MB）。**进程峰值驻留 7358 MB。**

## 9. 一处必须更正的旧说法（我在上一份检查点里说过、且说错了）

上一份检查点/本轮汇报里我说「`.venv/Scripts/pythonw.exe` 与 `Anaconda3/pythonw.exe` 是**硬链接**」。**实测推翻**：

| | 尺寸 | 链接数 | 硬链接列表 |
|---|---|---|---|
| `.venv/Scripts/pythonw.exe` | 256,784 | **1** | 只有它自己 |
| `Anaconda3/pythonw.exe` | 102,680 | 2 | `pkgs\python-3.12.4-h14ffc60_1\pythonw.exe` 与 `anaconda3\pythonw.exe` |

真相：venv 那个是**独立的重定向器**，运行时把 base 解释器拉起为**子进程**；子进程实测 `sys.prefix` = venv、`sherpa_onnx` 取自 venv 的 site-packages。所以任务管理器里看到的 `Anaconda3\pythonw.exe` 是子进程，**不是环境错乱**，也不影响依赖隔离。
